# Canonical result tables

Small, committed tables that back the main-figure and Supplementary-table numbers, so
every headline value regenerates from a tracked file. Figure-generation sources are kept
in the local staging backup until the manuscript text is accepted for release. Previously
these lived under `results/_remote/unified/` (gitignored); they are promoted here for
reproducibility.

Convention note: PDS has two documented conventions. The **multi-seed** convention (these
tables) is what the main text reports (in-house PDS 0.471-0.489; all in-house CIs overlap 0.50 except KNN-theta, whose interval lies entirely below it). The
**single-draw** grid (`results/results_v4_10metrics.csv`, `results/bootstrap_CIs.json`,
and the ESM2/AlphaMissense grid `results/reviewer_controls/rep_grid_summary.csv` plus
`am_summary.csv`) gives lower values (~0.46) and backs the single-draw
column. The representation grid was re-run on 2026-07-30 with all six regression heads after a
positional-argument defect was found to have silently dropped the MLP head; see
`results/reviewer_controls/README.md` and `results/deprecated/README.md`. The new range is
PDS-cosine 0.458--0.473 and Pearson-delta 0.628--0.659 over nine representations.

Numbering note: the "Backs" column uses **printed** figure and Supplementary-table numbers,
the ones a reader of the final PDFs sees. Figure-generation sources are withheld from the
public checkout for the current staging pass.
Rows below were re-checked against the current manuscript on 2026-08-17, when several of them
still carried the pre-compression Supplementary numbering (the SI defines ten tables, not
twelve).

The evaluation harness and the canonical scorer are committed at
`scripts/analysis/harness.py` and `scripts/analysis/score_definitive.py`; before this they
existed only in the compute workspace. Two checks pin them to the published run: the
committed harness reproduces all 475 cached deterministic per-variant profiles byte for
byte, and `train_only_grid.py --standardization all-cell` reproduces
`definitive_summary_allcell.csv` to within rounding (18-head mean 0.4876 variant-clustered,
0.4995 cell-wise; max per-method difference 0.0005).

`best_model_pds.csv` is regenerated by `remote_data.best_model()` (max over the 18 in-house
heads of the per-gene mean PDS_cos in `per_seed_variant_pds.csv.gz`, which is what `remote_data.best_model()` reads); the CSV is the pinned copy.

The three `residual_axis_*.csv` files were regenerated on 2026-08-04 by
`scripts/analysis/residual_axis.py` after a scoring defect was found. scVIDR's JAK1
predictions are non-finite; the unguarded ranking function returned `1 + 0.5/(n_g-1)` = 1.020
for each of that gene's 26 variants, a value above the metric's range, which had put scVIDR at
PDS 0.540 and residual-PDS 0.557. The residual-axis tables refuse and count those predictions,
and score scVIDR on the 282 variants where it produced a finite prediction: PDS 0.496 and
residual-PDS 0.514. Every other method is bit-identical to the pre-fix run, and the ceiling
file is unchanged because it scores a second measurement rather than a model prediction.

The main multi-seed PDS table uses the separately documented no-ranking convention so that
the common query cohort is retained: each of the 26 non-finite JAK1 queries receives PDS 0.5.
Accordingly, `definitive_summary.csv` reports scVIDR over 308 PDS queries (PDS 0.4856,
95% CI 0.4605--0.5109), records the 26 affected variants in `n_refused`, and has finite
prediction coverage of 282. Re-pooling `per_seed_variant_pds.csv.gz` reproduces the
chance-assigned primary distinct-variant estimate. The current
`scripts/analysis/repool_per_seed.py --check` still reports a provenance-only mismatch in
the unused scVIDR secondary cell-level interval (`cell_lo` 0.4792 versus 0.4780 and
`cell_hi` 0.5293 versus 0.5283); the primary PDS point estimate and interval match.
The script's `--convention refuse` option produces the finite-only sensitivity estimate
(n=282, PDS 0.4843, 95% CI 0.4552--0.5119).

`pairwise_resolvability.csv` and `classifier_two_sample.csv` are computed on the curated
benchmark variant set (KRAS n=92, via the `pertresolve_bench.csv` BENCH filter), matching
every other analysis; the plotted printed-Fig-4d/4e values are unchanged from the pre-restriction run
(KRAS was already at the floor), so this is a traceability-consistency fix only.
